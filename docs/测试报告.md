**方法**：对全量仿真库（2 万商品 / 200 万销售单）经真实 HTTP 调用；每场景预热后连续采样，nearest-rank 法取 P50/P95；单实例部署、同机压测客户端。

## 11. 结论与局限

1. **结论**：全部 Must 级功能与 §7 验收条款（AC-01~AC-20）均具备自动化或实测证据并通过；交付物（容器化、部署脚本、六份文档、仿真数据）齐备。
2. **局限**：
   - 性能为单机抽样（非持续压力测试），P95 采样量较小（20/10/15），用于对照 AC-20 基线而非容量评估；
   - 并发验证聚焦库存扣减（AC-08），未做多收银台混合负载压测；
   - 前端以无头浏览器路径验证 + 人工操作截图，未建 UI 自动化回归套件；
   - FR-RPT-09（单据打印）/ FR-RPT-10（自定义报表）为已知未交付项，首页有明示提示，不在本次验收范围内；
   - V1.1 异步任务的结果文件落在容器本地目录且默认保留 24h（任务记录与状态在库中可审计）；未验证“容器重建后重新下载”路径，属设计取舍（见《部署与运维手册》§5.6）；
   - `POST /goods/import/failed-export`（导入失败行导出）仍为同步实现：其入参是用户重新上传的失败文件，无法在提交时持久化到任务中异步处理，且输出规模受上传行数限制。
