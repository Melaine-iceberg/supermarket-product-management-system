# 从本机迁移到云服务器（VPS + Cloudflare Tunnel）

> 目标：把 MySQL / 后端 / Nginx 从本机 Docker 搬到一台常开的云服务器，保留现有域名
> `https://smms.sadd.pw` 与已录入的数据，本机不再承担服务。
> 前置条件：项目已完全容器化（`docker-compose.yml` + `backend/Dockerfile` + `frontend/Dockerfile`），
> 因此本次迁移**不需要改任何代码**。

## 0 目标架构

```
浏览器 → Cloudflare 边缘 →[出站隧道]→ cloudflared(VPS) → nginx:80 → /api → backend:8080 → mysql:3306
```

VPS 上三个业务端口全部只绑 `127.0.0.1`，不开放任何入站端口（仅保留 SSH，建议限制来源 IP）。

## 1 前置条件

| 项目 | 要求 | 说明 |
|---|---|---|
| 规格 | 2 核 4 GB 起，系统盘 ≥ 40 GB | 后端镜像在服务器上构建时 Gradle + JDK 25 峰值约 1.5~2 GB；2 GB 内存机型请走 §6 的「本地构建 + 传镜像」 |
| 系统 | Ubuntu 22.04 / 24.04 或 Debian 12 | 其它发行版把包管理命令换掉即可 |
| 软件 | Docker Engine + Compose v2 | 安装见 §2.1 |
| 网络 | 出站 443 可达 Cloudflare 边缘 | 隧道为出站连接，**无需公网入站端口、无需备案** |
| 代码 | GitHub `Melaine-iceberg/supermarket-product-management-system` 的 `main` | 本次迁移基于提交 `8d765ff`（与本机验证过的版本一致） |

## 2 服务器初始化

### 2.1 安装 Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"      # 重新登录后生效
docker compose version               # 需 v2.x
```

### 2.2 时间同步（影响 JWT 过期、任务留痕时间）

```bash
timedatectl status          # 确认 System clock synchronized: yes
sudo timedatectl set-timezone Asia/Shanghai   # 可选，容器内 TZ 已在 compose 中固定为 Asia/Shanghai
sudo apt-get install -y chrony && sudo systemctl enable --now chrony
```

## 3 部署代码与配置

### 3.1 拉取代码

```bash
git clone https://github.com/Melaine-iceberg/supermarket-product-management-system.git ~/smms
cd ~/smms
git checkout 8d765ff          # 锁定本次验证过的提交；确认无误后可改跟 main
```

### 3.2 生成 `.env`（不入库，必须手工创建）

```bash
cat > ~/smms/.env <<EOF
# 端口：VPS 上无本地开发环境冲突，用默认值；全部只绑回环
SMMS_WEB_PORT=80
SMMS_SERVER_PORT=8080
SMMS_MYSQL_PORT=3306

# 密码：生产环境务必更换为随机值（仅首次初始化数据卷时生效）
SMMS_DB_ROOT_PASSWORD=$(openssl rand -base64 24 | tr -d '/+=' | head -c 24)
SMMS_DB_PASSWORD=$(openssl rand -base64 24 | tr -d '/+=' | head -c 24)
SMMS_JWT_SECRET=$(openssl rand -base64 48)

# 域名白名单：浏览器 POST 即使同源也会带 Origin，未列白名单会 403 Invalid CORS request
SMMS_CORS_ORIGINS=https://smms.sadd.pw

# Cloudflare Tunnel 凭据（见 §5；先留空则不起 cloudflared）
SMMS_TUNNEL_TOKEN=

# 只保留隧道一条入口，关闭直连
SMMS_WEB_BIND=127.0.0.1
SMMS_SERVER_BIND=127.0.0.1
SMMS_MYSQL_BIND=127.0.0.1
EOF
chmod 600 ~/smms/.env
```

> `SMMS_JWT_SECRET` 更换后**已签发的 token 全部失效**，所有用户需重新登录一次，业务数据不受影响。
> 数据库密码更换不影响已有数据：dump 中不含 `CREATE USER`/`GRANT`，`smms` 账号由 MySQL 镜像首次初始化创建。

## 4 数据迁移（本机 → VPS）

### 4.1 本机导出

已完成，产物：`~/smms-migration/smms_<日期>.sql`（21 MB，43 张表）。

重新导出（如需）：

```bash
mkdir -p ~/smms-migration && cd ~/smms-migration
docker exec smms-mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" \
  --single-transaction --routines --triggers --default-character-set=utf8mb4 \
  --set-gtid-purged=OFF smms' > smms_$(date +%F).sql
tail -1 smms_$(date +%F).sql      # 期望：-- Dump completed on ...
```

### 4.2 传到 VPS

```bash
scp ~/smms-migration/smms_*.sql <user>@<VPS_IP>:~/smms/
```

### 4.3 先只起 MySQL 并导入

```bash
cd ~/smms
docker compose up -d mysql
docker compose ps                              # 等 mysql 变 healthy（首次初始化 30~60s）

# 导入（-T 关闭伪终端，避免管道被吞）
docker compose exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" smms' \
  < smms_$(date +%F).sql

# 校验（期望 goods=500、sales_order=19977、sys_user=10、member=300）
docker compose exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -N -e "
  select \"goods\",count(*) from smms.goods
  union all select \"sales_order\",count(*) from smms.sales_order
  union all select \"sys_user\",count(*) from smms.sys_user
  union all select \"member\",count(*) from smms.member;"'
```

> `db/schema.sql` 与 `db/init-data.sql` 会在数据卷首次初始化时自动执行，但导入的 dump 自带
> `DROP TABLE IF EXISTS`，会完整覆盖，无需手工清理。

## 5 Cloudflare Tunnel 切换

同一域名同一时刻只能有一条隧道的公共主机名，因此有两种做法：

### 方案 A：复用现有隧道（改动最小）

```bash
# 1) 把本机 .env 里的 SMMS_TUNNEL_TOKEN 复制到 VPS 的 ~/smms/.env
# 2) 必须先停掉本机连接器，否则 Cloudflare 会在两条连接器间轮询，部分请求仍落回你的 PC
cd ~/code/supermarket-product-management-system
docker compose --profile tunnel stop cloudflared

# 3) VPS 上启动全栈
cd ~/smms && docker compose --profile tunnel up -d --build
```

### 方案 B：新建隧道 + 先验收再切域名（推荐，可零感知回滚）

1. Zero Trust → Networks → Tunnels → 新建 `smms-vps`（cloudflared 类型）；
2. 公共主机名先填**临时域名**：`smms-vps.sadd.pw`，服务类型 `HTTP`，URL `nginx:80`；
3. VPS 的 `.env` 填该隧道 token，`SMMS_CORS_ORIGINS` 临时加上 `https://smms-vps.sadd.pw`，
   然后 `docker compose --profile tunnel up -d --build`；
4. 用 `https://smms-vps.sadd.pw` 完整验收（§7）；
5. 验收通过后，在 `smms-vps` 隧道里**添加** `smms.sadd.pw` → `http://nginx:80`，
   在旧隧道里**删除**同主机名。DNS 记录会自动切到新隧道，旧连接器随即失效；
6. 把 `.env` 的 `SMMS_CORS_ORIGINS` 改回 `https://smms.sadd.pw`，`docker compose up -d backend`；
7. 本机 `docker compose --profile tunnel stop cloudflared`（**只 stop，不要 down/删卷**，留作回滚）。

## 6 2 GB 内存机型的替代构建方式

```bash
# 本机构建并导出镜像
cd ~/code/supermarket-product-management-system
docker compose build
docker save smms-backend smms-nginx | gzip > /tmp/smms-images.tar.gz
scp /tmp/smms-images.tar.gz <user>@<VPS_IP>:~/

# VPS 导入后直接启动（不再 --build）
gunzip -c ~/smms-images.tar.gz | docker load
cd ~/smms && docker compose --profile tunnel up -d
```

或在 VPS 加 2 GB swap：`sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile`。

## 7 验收清单

```bash
cd ~/smms
docker compose ps                      # mysql/backend/nginx/cloudflared 均 Up（前三者 healthy）

# 本机回环（不经 Cloudflare，验证后端本体）
curl -s http://127.0.0.1:8080/actuator/health        # {"status":"UP"}
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/   # 200

# 公网
curl -s -o /dev/null -w '%{http_code}\n' https://smms.sadd.pw/          # 200
curl -s https://smms.sadd.pw/api/actuator/health                       # {"code":401,...} 属正常（未带 token）

# 端口暴露面自查：三个业务端口应只有 127.0.0.1，不得出现 0.0.0.0
sudo ss -ltnp | grep -E ':(80|8080|3306)\b'
```

浏览器端：

1. 登录一次（管理端账号见 `db/init-data.sql`），页面所有列表/报表正常；
2. 导出报表、导入商品各试一次（异步任务链路）；
3. 核对真实客户端 IP 还原：`SELECT ip,created_at FROM smms.login_log ORDER BY id DESC LIMIT 5;`
   应是你当前的**公网** IP，而非容器内网地址；
4. 断网重连后再登录一次，确认 token 正常。

## 8 回滚

回滚成本极低，切换后的 1~2 周内保持本机栈**停止但不删除**：

```bash
# 回滚到本机
cd ~/smms && docker compose --profile tunnel stop
# Cloudflare 侧把 smms.sadd.pw 的主机名改回旧隧道（方案 B）或直接复用同一 token（方案 A）
cd ~/code/supermarket-product-management-system && docker compose --profile tunnel start cloudflared
```

> 注意：切换期间若两个环境同时写入同一业务数据，会出现分叉。回滚后以本机数据为准，
> VPS 上的新数据需另行导出合并。

## 9 迁移后的运维差异

| 项目 | 说明 |
|---|---|
| 备份 | `docs/部署与运维手册.md` §5.1 的命令在 VPS 上同样适用；建议加 cron 每日低峰导出并保留 14 天 |
| 异步任务结果文件 | 容器内 `/app/task-files` **非持久化**，容器重建即丢失（任务记录仍在库）。如需长期保留，给 `backend` 加卷映射 `./data/task-files:/app/task-files` 并调大 `SMMS_TASK_RETAIN_HOURS` |
| 老库升级脚本 | 本次导入的是当前版本完整 dump，**无需**再执行 `db/upgrade-1.1-async-task.sql` |
| 安全 | 本机 `.env` 中的隧道 token 已用于生产，建议迁移完成后在 Zero Trust 里轮换一次；SSH 改密钥登录并限制来源 IP；关闭 root 密码登录 |
| 域名白名单 | 只要访问域名变化（含临时域名），就必须同步 `SMMS_CORS_ORIGINS`，否则登录报「网络异常」（实为 403 Invalid CORS request） |
