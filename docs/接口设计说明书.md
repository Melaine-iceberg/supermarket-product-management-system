## 1 通用约定

### 1.1 基础约定

| 项 | 约定 |
| --- | --- |
| 基础路径 | `/api/v1`（生产环境经 Nginx 反向代理 `/api/` → `backend:8080`） |
| 传输 | HTTP/1.1，JSON 请求/响应，`Content-Type: application/json; charset=utf-8`（文件上传为 `multipart/form-data`） |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（时区 Asia/Shanghai）；日期参数 `yyyy-MM-dd`（ISO Date） |
| 金额/数量 | JSON number；金额最多 2 位小数，称重数量最多 3 位小数（服务端 BigDecimal 校验） |
| 大小写 | 字段 camelCase（Jackson 映射数据库 snake_case） |

### 1.2 统一响应结构（IR-SW-01）

```json
{
  "code": 0,
  "message": "成功",
  "data": { },
  "timestamp": "2026-10-06 12:00:00"
}
```

- `code = 0` 成功；非 0 为业务错误码（见附录 B），`message` 为可直接展示的中文提示；
- `data` 为 null 时不序列化（`@JsonInclude(NON_NULL)`）；
- 业务失败（含参数校验失败）HTTP 状态仍为 200，以 `code` 区分；鉴权失败由安全过滤链返回 401/403 同构体。

### 1.3 分页与排序约定（IR-COM-04）

| 项 | 约定 |
| --- | --- |
| 请求参数 | `page`（默认 1）、`size`（默认 20，最大 100） |
| 响应结构 | `data: { "list": [...], "total": 0 }`（`PageVO`） |
| 默认排序 | 单据/流水类按时间倒序；档案类按 `id`/编码升序 |
| 排序参数 | 部分报表支持 `orderBy` 枚举（如商品排行 `orderBy=qty|salesAmount|profitAmount|netSalesAmount`），非法值回落默认 |

### 1.4 认证与鉴权

| 项 | 约定 |
| --- | --- |
| 登录 | `POST /api/v1/auth/login` 获取 `token`（JWT，HMAC-SHA，算法随密钥长度自动选择） |
| 令牌传递 | 所有受保护接口携带 `Authorization: Bearer <token>` |
| 权限码 | 后端方法级 `@RequirePerm("sys:xxx:yyy")` + AOP 校验；前端路由 `meta.perm` 同步拦截（双重校验 BR-SYS-05） |
| 登录失效 | 登出/账号停用/权限变更/改密后旧令牌即时失效（黑名单 + 权限版本，IR-SW-03） |
| 公开接口 | `auth/login`、`auth/store-name`、`ping`、`actuator/health` |

### 1.5 防重与并发约定（NFR-REL-02）

写操作类接口（结算、退货等）请求体可携带 `requestToken`（每次操作前端生成 UUID，长度 ≤64）。服务端以唯一键兜底：同令牌重复请求不重复落库，直接返回首次结果（重放）。

### 1.6 文件与导出

| 项 | 约定 |
| --- | --- |
| 导入 | `multipart/form-data`，xlsx 模板；大小限制 10MB（反代 20MB）；先校验后提交两阶段 |
| 导入提交 | 异步任务：上传后立即返回 `taskNo`，后台单事务导入，轮询完成后返回导入报告 |
| 导出 | 异步任务：提交后立即返回 `taskNo`，后台生成 xlsx，轮询完成后从任务下载接口取文件（`Content-Disposition: attachment`）；单次上限 `export_max_rows`（默认 50000 行），超限任务转为失败并提示 |
| 打印 | 小票由前端按结算返回数据渲染（58/80mm 参数化），无服务端 PDF 接口 |

> **为何异步（2026-10 起）**：早期版本导出/导入提交为同步 `ResponseEntity<byte[]>`，大范围报表（2 万商品 / 200 万单据量级）耗时可能超过反向代理源站超时（Cloudflare 约 100s，返回 524），长连接被中断且用户无反馈。现改为「提交 → 轮询进度 → 完成下载」三段式，提交响应稳定在 1s 内，彻底规避代理超时。任务与结果文件保留 24 小时，见 §3.11。

## 3 典型接口详述

### 3.1 登录 `POST /api/v1/auth/login`（公开）

请求：

```json
{ "username": "cashier", "password": "Cashier@2026" }
```

响应（`LoginResponse`）：

```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "expiresInSeconds": 28800,
    "mustChangePwd": false,
    "user": { "id": 5, "username": "cashier", "realName": "王收银", "roles": ["CASHIER"], "perms": ["sys:cashier:enter", "..."] },
    "menus": [ { "name": "收银台", "routePath": "/sale/cashier", "children": [] } ]
  },
  "timestamp": "2026-10-06 12:00:00"
}
```

失败：`{"code":1101,"message":"用户名或密码错误"}`；连续失败 5 次返回 `1102` 账号锁定；停用账号返回 `1103`。

### 3.2 收银结算 `POST /api/v1/sales/checkout`

权限码 `sys:cashier:enter`。请求（`CheckoutCommand`）：

```json
{
  "counterNo": 1,
  "memberId": 1001,
  "orderDiscountRate": 0.9,
  "authorizerUsername": "manager",
  "authorizerPassword": "***",
  "discountReason": "会员日促销",
  "items": [
    { "goodsId": 10001, "quantity": 2, "netWeight": null, "remark": null, "overridePrice": null, "priceReason": null },
    { "goodsId": 10002, "quantity": 0.526, "netWeight": 0.526, "remark": null, "overridePrice": 8.8, "priceReason": "临期折价" },
    { "goodsId": null, "tempName": "购物袋", "tempAmount": 0.5, "quantity": 1, "netWeight": null, "remark": null, "overridePrice": null, "priceReason": null }
  ],
  "payments": [
    { "payType": "BALANCE", "amount": 30.00 },
    { "payType": "CASH", "amount": 20.00 }
  ],
  "requestToken": "7f3c2b1a-...."
}
```

要点：整单折扣低于下限（参数 `min_discount_rate`）或存在单品改价时必填店长授权（授权人 ≠ 当前收银员，错误码 1516）；无码商品以 `tempName/tempAmount` 登记（错误码 1515）；**最终折扣率 = 会员等级折扣 × 整单折扣，低于下限同样拒绝 `1508`（GAP-P0-09/BR-SALE-10）**。

**收银台录入辅助（GAP-P0-06）**：`GET /api/v1/sales/cashier/categories`（仅启用分类树）与 `GET /api/v1/sales/cashier/browse?categoryId=&page=&size=`（启用商品分页，分类含子分类）均按 `sys:cashier:enter` 鉴权，收银员无 `sys:cat:list`/`sys:goods:list` 也能完成"分类树浏览点选"录入方式（FR-SALE-02③）。

响应（`CheckoutVO`）：

```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "orderId": 90001,
    "orderNo": "XS20261006010001",
    "itemCount": 4,
    "goodsAmount": "58.63",
    "memberDiscountAmount": "2.93",
    "orderDiscountAmount": "2.93",
    "discountAmount": "5.86",
    "payableAmount": "52.77",
    "paidAmount": "52.77",
    "changeAmount": "0.00",
    "payments": [ { "payType": "BALANCE", "amount": "30.00" }, { "payType": "CASH", "amount": "22.77" } ],
    "memberLevelUpgraded": "银卡会员",
    "saleTime": "2026-10-06 12:00:00"
  },
  "timestamp": "2026-10-06 12:00:00"
}
```

失败场景：库存不足 `1401`（含可售数量提示）、应收不足 `1507`、同商品多行 `1502`、称重缺净重 `1504`、会员停用 `1510`；整单任何一步失败全部回滚（AC-09）。

### 3.3 销售退货 `POST /api/v1/sales/returns`

权限码 `sys:ret:create`。请求（`ReturnCreateRequest`）：

```json
{
  "salesOrderId": 90001,
  "refundType": "CASH",
  "returnReason": "QUALITY",
  "reasonRemark": "包装破损",
  "authorizerUsername": "manager",
  "authorizerPassword": "***",
  "items": [ { "salesItemId": 900011, "returnQty": 1, "remark": null } ],
  "requestToken": "9a8b7c6d-...."
}
```

校验要点：退货有效期（参数 `return_valid_days`）超期须特批 `1525`；退款超阈值（`return_auth_amount`）或"误操作"原因须店长授权 `1526`，授权人 = 发起人拒绝 `1527`；超退数量 `1523`；商品不允许退货 `1524`。

### 3.4 采购单审核 `PUT /api/v1/purchase-orders/{id}/audit`

权限码 `sys:pur:audit`（店长）。请求：`{ "approved": true, "reason": null }`；驳回必填原因（`1806`）。状态机非法转换返回 `1802`。

### 3.5 入库验收 `POST /api/v1/receipt-orders`

权限码 `sys:rcv:create`（库管员）。请求（`ReceiptCreateRequest`）核心字段：`purchaseOrderId`、明细 `[{ "purchaseItemId": 1, "receivedQty": 100, "receivedPrice": 12.50, "remark": null }]`、授权信息（超容差时）。

校验要点：超收容差 `1812` 或价差容差 `1813` 须店长授权；验收人 = 采购单创建人触发职责分离（GAP-P1-08 统一策略：默认放行并记异常日志，参数 `duty_separation_strict=true` 时拒绝 `1814`，超级管理员可代验且留痕，AC-13）。落库后按移动加权重算结存成本（AC-03）。

**待入库选单（GAP-P0-05）**：`GET /api/v1/receipt-orders/pickable`（仅 APPROVED/PARTIAL，`orderNo` 可选）与 `GET /api/v1/receipt-orders/pickable/{id}`（验收明细）按 `sys:rcv:list` 鉴权，库管员无需采购单菜单权限 `sys:pur:list` 即可走通"选单 → 验收 → 打印"主流程。

### 3.6 盘点审核 `POST /api/v1/stock-checks/{id}/audit`

权限码 `sys:check:audit`（店长）。请求：`{ "password": "***", "approved": true, "rejectReason": null }`（敏感操作二次确认 BR-SYS-06）。审核通过后结存覆盖为实盘数并生成盘盈/盘亏流水；差异原因存数据字典 `check_diff_reason` 代码（GAP-P1-09，非法/停用项返回 `1416`）；盘点人 = 审核人按职责分离统一策略处理：默认放行并记异常日志、`duty_separation_strict=true` 拒绝 `1414`、超级管理员可代审并留痕（GAP-P1-08）。

### 3.7 库存流水分页 `GET /api/v1/inventory/records`

权限码 `sys:inv-record:list`。查询参数：`goodsId`、`goodsName`、`recordType`、`bizNo`、`operatorName`、`beginDate`、`endDate`、`page`、`size`。响应 `PageVO<InventoryRecordVO>`，关键字段：`goodsName/recordType/changeQty/beforeQty/afterQty/unitCost/bizType/bizNo/operatorName/operateTime`（前后结存供审计链校验，BR-INV-08）。

### 3.8 销售日报 `GET /api/v1/report/sales/daily`

权限码 `sys:rpt:sales`。参数：`beginDate`、`endDate`（必填区间）。响应 `SalesReportVO`：销售额、优惠额、退货额、净销售（净销售 = 销售额 − 优惠额 − 退货额，BR-RPT-01）、客流量/客单价、毛利（按角色屏蔽）等汇总；成本/毛利字段对无权限角色返回 null。

### 3.9 汇总下钻 `GET /api/v1/report/sales/drill-orders`

权限码 `sys:rpt:sales`。参数与日报聚合维度对齐：`beginDate/endDate/payType/hour/cashierName/counterNo/memberOnly/page/size`。响应 `PageVO<DrillOrderRow>`：构成汇总数字的销售单列表（单号/收银员/收银台/时间/金额/退货状态），点击可进入单据详情（BR-RPT-06/AC-16）。

### 3.10 报表导出（异步任务）`GET /api/v1/report/{goods|sales|inventory|profit|purchase|member}/export`

按当前筛选条件提交导出任务，**立即返回任务号**（不等待生成）；超 `export_max_rows` 时任务转为失败并给出提示；任务提交与完成均记入操作日志（FR-RPT-08）。同批改造的端点还有 `GET /goods/export`、`GET /oplogs/export`、`GET /inventory/alerts/export`、`POST /goods/import/commit`、`POST /members/import/commit`。

**响应**（`data` 为任务视图，字段同 §3.11）

```json
{
  "code": 0,
  "data": {
    "taskNo": "9a9ec644909948708562dc108bb80952",
    "taskType": "EXPORT",
    "bizType": "SALES_REPORT_EXPORT",
    "bizName": "销售报表导出",
    "status": "QUEUED",
    "progress": 0,
    "phase": "已提交，等待执行",
    "expiresAt": "2026-10-08 13:52:59"
  },
  "message": "成功"
}
```

调用序列：提交导出 → 每 1s 轮询 `GET /tasks/{taskNo}` → `status=SUCCESS` 后 `GET /tasks/{taskNo}/download` 取文件；`status=FAILED` 时展示 `errorMessage`。

### 3.11 异步任务 `GET /api/v1/tasks/{taskNo}` 与 `GET /api/v1/tasks/{taskNo}/download`

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/tasks/{taskNo}` | 查询任务状态；**仅提交人可见**（非提交人 1902）；过期任务惰性转失败（1905） |
| `GET /api/v1/tasks/{taskNo}/download` | 下载结果文件（xlsx）；任务未完成 1903，文件被清理 1905 |

**任务状态机**：`QUEUED`（排队）→ `RUNNING`（执行中）→ `SUCCESS` / `FAILED`；服务重启时未完成任务在启动阶段统一置为 `FAILED`（提示重新提交），过期任务（默认 24h）由定时任务清理记录与文件。

**任务视图字段**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `taskNo` | string(32) | 任务号，提交响应返回，后续查询/下载凭据 |
| `taskType` | string | `EXPORT` / `IMPORT` |
| `bizType` | string | 业务类型，如 `SALES_REPORT_EXPORT`、`GOODS_IMPORT` |
| `bizName` | string | 任务名称（前端展示） |
| `status` | string | `QUEUED`/`RUNNING`/`SUCCESS`/`FAILED` |
| `progress` | int | 进度百分比 0~100 |
| `phase` | string | 当前阶段描述（如「正在生成数据」） |
| `fileName` / `fileSize` | string / long | 结果文件名与字节数（导出类） |
| `result` | object | 导入类任务的结果摘要（行数、成功/失败统计），导出类为 null |
| `errorMessage` | string | 失败原因 |
| `createTime` / `finishTime` / `expiresAt` | datetime | 提交/完成/过期时间 |

## 4 错误码

错误码分段：`0` 成功；`4xx/5xx` 通用；`1000+` 通用业务；`1100~1199` 系统；`1200~1299` 分类；`1300~1399` 商品；`1400~1499` 库存；`1500~1599` 销售；`1600~1699` 会员；`1700~1799` 供应商；`1800~1899` 采购；`1900~1999` 异步任务。全量清单（128 个）见附录 B。

## 5 前后端对接说明

1. **axios 实例**（`frontend/src/api/request.ts`）：`baseURL=/api/v1`；请求拦截注入 `Authorization: Bearer`；响应拦截对 `code!=0` 统一弹错（ElMessage），401 清除登录态并跳登录页，403 跳 403 页；
2. **登录态**（`stores/auth.ts`）：登录后持久化 token 与用户信息/权限码集合；路由守卫按 `meta.perm` 判定菜单可达性；
3. **动态菜单**：登录响应 `menus` 为按权限过滤的路由树，`MainLayout` 渲染侧边菜单；页面组件懒加载；
4. **防重**：结算/退货页面提交前生成 `requestToken`（`crypto.randomUUID()`），失败重试复用同一令牌，避免重复落单；
5. **导出/导入（异步任务）**：`api/task.ts` 封装 `runExportTask`/`runImportTask`——提交拿到 `taskNo` 后弹出进度对话框并按 1s 轮询 `GET /tasks/{taskNo}`，`SUCCESS` 时自动下载（`responseType: 'blob'` + 文件名解析）并关闭弹窗，`FAILED` 时展示原因；轮询遇 401 自动重新登录重试、404 自动重新提交（应对服务重启）。业务 API 模块（`report.ts`/`goods.ts`/`member.ts`/`inventory.ts`/`system.ts`）返回 Promise，页面调用方式不变。

对接示例（结算页面核心调用链）：

```ts
// api/sale.ts
export const checkout = (data: CheckoutCommand) =>
  request.post<CheckoutVO>('/sales/checkout', data)

// 页面提交（简化）
const vo = await checkout({ ...form, requestToken: crypto.randomUUID() })
ElMessage.success(`结算成功：${vo.orderNo}，找零 ${vo.changeAmount}`)
```
