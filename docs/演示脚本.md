| 项目 | 说明 |
| --- | --- |
| 适用场景 | 课程项目演示、毕业设计答辩、录屏讲解 |

## 1. 演示前准备

### 1.1 确认环境

在仓库根目录执行：

```bash
docker compose ps
curl -fsS http://localhost:8080/actuator/health
```

期望结果：

- `smms-mysql`、`smms-backend`、`smms-nginx` 均为 `healthy`；
- 健康检查返回 `"status":"UP"`；
- 浏览器访问 `http://localhost` 正常。

### 1.5 录前数据库快照（强烈建议）

收银、审核、入库都会修改业务数据；想录第二遍时用快照恢复。

```bash
# 录制前快照
docker exec smms-mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" \
  --single-transaction --routines --triggers --databases smms' \
  > /tmp/smms-demo-before.sql
```

重录前恢复：

```bash
docker compose stop backend nginx
docker exec -i smms-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' \
  < /tmp/smms-demo-before.sql
docker compose start backend nginx
```

恢复后如果页面提示登录失效，重新登录一次即可。

不要追求一镜到底。按 6 段录制，后期剪掉登录和加载过程：

6. 系统管理与审计（管理员）

## 3. 标准版分镜脚本

### 3.1 0:00–0:35 开场

**画面**：登录页，或提前准备的封面/架构图。

**口播参考**：

> 大家好，这是我的项目《超市商品管理系统 SMMS》，面向单门店中小超市，覆盖商品、库存、采购、销售、会员、报表和系统管理。技术栈是 Vue 3 + Spring Boot 4 + MySQL 8，前后端分离，Docker Compose 一键部署。下面我按一条真实业务链路演示。

---

### 3.2 0:35–1:30 登录与权限

**操作步骤**：

1. 使用 `cashier / Cashier@2026` 登录。
2. 进入首页后，指向左侧菜单：只有“会员管理”和“销售管理”。
3. 点右上角用户菜单，显示“陈收银 / 收银员”。
4. 口头补充：店长会多出报表、采购、库存、商品；只有管理员才有“系统管理”。

**口播参考**：

> 系统采用 RBAC 权限模型，菜单按角色动态生成；后端接口同样做权限校验，越权会返回 403。登录支持 72 小时“记住我”，连续输错 5 次锁定 15 分钟。

**注意**：不要现场故意输错密码，会真的锁定 15 分钟。

---

### 3.3 1:30–4:40 收银（核心场景）

**操作步骤**：

1. **销售管理 → 交班管理 → 开班**，台号输入 `1`，确定。
2. **销售管理 → 收银台**，进入全屏收银界面。
3. 检索框输入 `6900000005002`，回车。
4. 再输入 `80498`，回车；弹出“净重录入：本地苹果特级”，输入 `1.2`，点“加入明细”。
5. 点“识别会员”，输入 `13100000052`，查询，选中“郑涛”。
6. 指向会员区：`****0052`、金卡会员、95 折、积分 9390、储值 ¥1000。
7. 指向金额：商品总额 `¥29.11`，会员折扣 `¥1.46`，应收（预估）`¥27.65`。
8. 按 `F2` 或点“结算”；收款弹窗会调用后端试算，显示 **应收（结算）`¥26.46`**，点“储值 ¥26.46”（或“金额=应收”），确认结算。
9. 展示成功信息：单号、找零；本次用储值支付，默认“储值消费不计积分”（`point_include_recharge=false`），积分不变是正常的。
10. 可选：按 `F4` 挂单，再点“取单”恢复，展示挂单/取单；时间紧可跳过。
11. 可选：**销售管理 → 交班管理**，在班班次现在会实时显示单数 `1`、净销售 `¥26.46`、储值 `¥26.46`；点“交班”可展示交班单。

**口播参考**：

> 收银台支持条码、编码、PLU、拼音首字母和分类浏览；称重商品必须录净重，金额按单价 × 净重。会员手机号对收银员脱敏，只显示后四位。结算时销售单、销售明细、库存扣减、库存流水、会员积分和储值在同一个事务里完成；库存用条件更新扣减，并发下不会超卖。

**关键提醒**：

- 必须先开班，否则销售单的 `shift_id` 为空，交班统计看不到这笔。
- 购物车上的 `¥27.65` 是前端按零售价估算；后端会优先取会员价（面粉 19.52 + 苹果 6.94×1.2），再打 95 折，精确应收是 **`¥26.46`**。收款弹窗会显示这个精确值，储值请按 `¥26.46` 支付。
- 储值不参与找零，所以储值金额不能超过后端应收；如果按 `¥27.65` 储值，会提示“储值支付额不得超过应收 26.46 元”。
- 这一单会让经营看板的“今日销售额”从 0 变成 **`¥27.85`**（商品总额/优惠前口径），实收和净销售是 **`¥26.46`**；销售报表里会显示“销售额 27.85 − 优惠 1.39 = 净销售 26.46”。讲解时建议把这两个口径说清楚。
- 如果提示库存不足，把数量改小或换商品，不要在现场反复试。

### 3.4 4:40–6:50 库存与盘点

**操作步骤**：

1. 切换到 `manager / Manager@2026`。
2. **库存管理 → 库存查询**，搜索“佳洁士”，展示结存从 185 变成 184，以及成本金额。
3. **库存管理 → 库存流水**，按商品“佳洁士”或今天日期查询，展示 `-1`、变动前/变动后、关联单号、操作人。
4. **库存管理 → 盘点管理**，打开 `PD202611230003`，点“详情”。
5. 勾选“只看差异行”，展示两行：
   - 百事面包精装：+2，差异金额 ¥19.76，原因“计数误差”；
   - 维达挂面：-1，差异金额 -¥7.27，原因“损耗”。
6. 点“审核通过”，输入当前账号密码 `Manager@2026`，确认通过。
7. 可选：**库存管理 → 库存体检**，展示“暂无数据”，说明理论结存与账面一致；一键修正仅超管可用。

**口播参考**：

> 库存流水只增不改不删，任何纠错都通过新增反向记录实现。盘点不是直接改库存，而是先快照账面数、录入实盘数、填差异原因，提交后由店长审核；审核通过才按实盘数覆盖结存，并生成盘盈/盘亏流水。审核要二次输入当前账号密码，而且盘点人和审核人要做职责分离。

**注意**：盘点审核**不可撤销**，正式录之前一定先做数据库快照。

### 3.5 6:50–9:20 采购闭环

#### A. 采购员：建议采购 + 提交采购单

1. 登录 `purchaser / Buyer@2026`。
2. **采购管理 → 建议采购**，展示公式和 4 条建议。
3. 指向“计算依据”列：
   `安全库存 50 × K 1.5 + 日均销量 0 × 提前期 7 天 − 结存 37 − 在途 0`
4. 指出“待指定供应商”的行不可勾选。
5. 可选：勾选“盼盼大米大瓶装”，点“生成草稿采购单”，展示供应商/数量/单价可改，然后取消（不生成）。
6. **采购管理 → 采购单**，找到 `PO202611230003`（草稿），点“提交”，确认。

#### B. 店长：审核采购单

7. 登录 `manager / Manager@2026`。
8. 点右上角“待办事项”，展示“待审核采购单 1”。
9. 进入 **采购管理 → 采购单**，找到刚提交的单，点“审核”。
10. 选择“通过”，输入 `Manager@2026`，确认。

#### C. 库管员：入库验收

11. 登录 `keeper / Keeper@2026`。
12. **采购管理 → 入库单 → 新建验收**。
13. 选择 `PO202611230003`，点“验收”。
14. 实收数量填 `1`，实收单价保持 `42.64`，确认入库。
15. 展示入库成功；可回“库存查询/流水”看库存增加和成本更新。

**口播参考**：

> 建议采购量是算出来的，不是拍脑袋，界面上能直接看到计算依据。采购单必须经过店长审核才能入库；入库只显示“已审核/部分入库”的单据。确认入库时，入库单、库存流水、结存、移动加权平均成本、采购单状态、供应商累计采购额在同一个事务里更新。超收或价差超出容差，需要店长现场授权；采购单创建人和验收人也要职责分离。

**备用方案**：如果 `PO202611230003` 不在待入库列表，用已审核的 `PO202611230002`（三只松鼠洗衣液 ×1，¥3.69）演示入库，效果一样。

### 3.6 9:20–11:20 报表与下钻

**操作步骤**：

1. 切回 `manager`。
2. **报表统计 → 经营看板**：
   - 今日销售额 `¥27.85`（商品总额/优惠前口径）、今日订单数 `1`；
   - 今日毛利额/毛利率（本单约 ¥5.98 / 22.6%）；
   - TOP10 热销商品；
   - 点“今日销售额”或“今日订单数”的“下钻”，展示刚才那笔销售单，再点单号看详情。
3. **报表统计 → 销售报表**：
   - 今日行：销售额 `¥27.85`、优惠 `¥1.39`、净销售 `¥26.46`；
   - 再点“上月”（当前为 2026-10，约 311 单 / ¥5.5 万），展示销售额、优惠额、净销售额、毛利额、毛利率、客单价；
   - 点“合计”行的“下钻”，展示构成它的销售单列表。
4. **报表统计 → 毛利分析**：选“上月”，展示毛利和负毛利行，说明成本按明细快照核算。
5. **报表统计 → 库存报表 / 会员报表**：各停 5～10 秒，点一下库存预警或会员贡献。
6. 可选：**报表统计 → 采购报表**。采购汇总按采购单营业日统计，本演示采购单是 `2026-11-23`，今天筛选会为空；请选“近 30 日”或手动选 `2026-11-23`。到货及时率只统计有“预计到货日”的采购单，`PO202611230003` 没有预计到货日，因此不会出现在到货及时率下钻里。

**口播参考**：

> 报表默认查询“今日”，演示历史数据要点“上月”或“近 30 日”。所有汇总数字都能下钻到构成它的单据，方便对账。毛利按明细成本快照计算，历史单据不会因为后来调价而变化；成本与毛利字段只对店长及以上可见。导出是后台任务，会显示进度，完成后自动下载。

**如果录制日期变化**：手动把日期选到 `2026-09-01 ～ 2026-09-30`，这是数据最丰富的一段（约 1624 单 / ¥33.5 万）。

### 3.7 11:20–12:40 系统管理与审计

**操作步骤**：

1. 切换到 `admin / Admin@2026`。
2. **系统管理 → 用户管理**：展示 5 个内置角色和用户，说明重置密码后下次登录强制改密、用户只能停用不能删除。
3. **系统管理 → 系统参数**：展示折扣下限、退货阈值/有效期等，说明“即时”和“延迟（≤60 秒，无需重启）”。
4. **系统管理 → 操作日志**：按今天/模块筛选，展示刚才的开班、结算、采购审核、入库、盘点审核记录。
5. **系统管理 → 登录日志**：展示登录成功/失败/锁定记录。
6. **系统管理 → 定时任务**：展示 6 个任务，说明每日备份、促销到期、挂单清理等。

**口播参考**：

> 关键操作都有审计留痕：谁、什么时间、在哪个模块、对哪张单、结果如何。敏感操作除了权限校验，还要二次输入当前账号密码。系统参数支持即时和延迟生效，常见参数调整不需要重启。

**注意**：不要在现场点“立即执行”定时任务或“一键备份”，可能改数据或等待较久；展示列表即可。

## 4. 录屏剪辑建议

- 按 6 段录制，每段开头重新登录对应角色，后期剪掉登录/加载过程。
- 角色切换处加字幕：`切换到：店长 manager`、`切换到：库管员 keeper`。
- 关键数字（应收、找零、盘盈/盘亏、建议采购量、净销售、毛利）停留 2 秒，可后期放大。
- 收银台和报表页可用系统自带“进入全屏”按钮，减少侧边栏干扰。
- 背景音乐低音量、无歌词；口播优先。

## 6. 常见翻车点与应对

| 风险 | 现象 | 应对 |
| --- | --- | --- |
| 今日数据为 0 | 看板、销售报表全是 0 | 先录收银；或报表点“上月”/手动选 2026-09 |
| 未开班 | 交班统计看不到刚录的销售 | 先“交班管理 → 开班”，再进收银台 |
| 审核忘输密码 | 盘点/采购审核提交不了 | 提前准备 `Manager@2026`，弹窗内输入当前账号密码 |
| 现场试错密码 | 账号锁定 15 分钟 | 不要演示错误密码；提前确认账号可登录 |
| 同一浏览器切角色 | 登录态互相覆盖 | 退出重登、独立 Chrome Profile，或分段录制 |
| 入库选单为空 | 看不到采购单 | 采购单必须先审核通过；或用 `PO202611230002` 备用 |
| 盘点审核不可撤销 | 录第二遍数据已变 | 录前 `mysqldump` 快照，录后恢复 |
| 报表默认今日 | 历史数据看不到 | 点“上月/近 30 日”，或手动选 2026-09 |
| PWA 安装提示 | 片头挂一个安装条 | 开录前点“以后再说” |
| 导出等待 | 点导出后一直转圈 | 导出是后台任务，展示进度弹窗即可，不要重复点 |

## 7. 演示时容易误判的点（不是 Bug）

| 现象 | 原因 | 建议 |
| --- | --- | --- |
| 看板“今日销售额”是 ¥27.85，实收却是 ¥26.46 | 看板/销售报表的“销售额”是商品总额（优惠前），净销售 = 销售额 − 优惠额 | 讲解“销售额 27.85 − 优惠 1.39 = 净销售 26.46” |
| 储值支付后会员积分不变 | 系统参数 `point_include_recharge=false`，默认储值消费不计积分 | 这是 BR-MEM-07 的默认口径；想展示积分增长可改用现金/银行卡/移动支付 |
| 采购报表选“今日”为空 | 采购汇总按采购单营业日 `business_date`（本演示单为 2026-11-23） | 选“近 30 日”或手动选 2026-11-23 |
| “到货及时率”里没有本次入库 | 该报表只统计有“预计到货日”的采购单，`PO202611230003` 没有预计到货日 | 演示时可跳过；或提前给采购单补预计到货日 |
| 操作日志里找不到“采购审核” | 实际动作名是“审核采购单”；入库动作名是“采购入库验收” | 按实际动作名筛选/查看 |
| 交班前看班次列表显示 0 单 | 旧版本只回写交班统计；现已改为在班班次实时计算 | 当前版本应显示单数/净销售额/储值金额 |
